# Saffari NeuroCare

سامانه مراقبت بیماران دکتر صفاری با اپ اندروید بیمار، اپ پزشک و دو وب‌اپ مستقل. **بک‌اند هدف نسخه فعلی Supabase Edge Functions + PostgreSQL است.** پوشه `backend/` نسخه قدیمی Node/Express است و در استقرار Supabase استفاده نمی‌شود.

## وب‌اپ‌ها
- بیمار: `https://app.mhsaffari.ir/`؛ فقط محتویات `web/patient/` را در Document Root جداگانه آن قرار دهید.
- پزشک: `https://doctor-app.mhsaffari.ir/`؛ فقط محتویات `web/doctor/` را در Document Root جداگانه آن قرار دهید.
- دو دامنه باید DNS و HTTPS مستقل داشته باشند؛ پنل پزشک از رابط بیمار جداست.

## ساختار کد
- `supabase/schema.sql`: schema با RLS فعال و دسترسی مستقیم محدود به Edge Function
- `supabase/functions/neurocare-api/index.ts`: API مشترک ثبت‌نام، ورود، نوبت‌ها، گزارش علائم، یادداشت‌های بالینی، برنامه پیگیری و داروها
- `supabase/config.toml`: تنظیم احراز هویت سفارشی Edge Function
- `web/patient/` و `web/doctor/`: وب‌اپ‌ها با نقش قفل‌شده در پیکربندی
- `mobile/` و `doctor_mobile/`: دو اپ Flutter

## استقرار
راهنمای فارسی: [supabase/README.md](supabase/README.md). قبل از انتشار، ساخت پروژه Supabase، اعمال schema، deploy تابع، ایجاد حساب پزشک، وارد کردن Publishable Key و API URL در پیکربندی و تنظیم DNS/SSL باید تکمیل شوند. مخزن عمومی نیست جای نگهداری رمز واقعی یا کلید Secret؛ هیچ‌کدام را Commit نکنید.

## وضعیت نسخه وب و امنیت
- نام کاربری بیمار در وب‌اپ کد ملی است؛ ثبت‌نام به نام، نام خانوادگی، کد ملی، شماره موبایل و حوزه پیگیری نیاز دارد.
- برای حساب‌های جدید، بیمار رمز مستقل ۸ تا ۱۲ نویسه‌ای با حروف انگلیسی، عدد و نماد انتخاب می‌کند. کپچای محاسباتی ساده و محدودیت تعداد تلاش‌ها برای مسیرهای ورود و ثبت‌نام فعال است.
- حساب‌های قدیمی ممکن است هنوز با روش اعتبارسنجی قبلی ایجاد شده باشند؛ پیش از ورود اطلاعات پزشکی واقعی، ورود حساب‌های قدیمی و فرایند تعیین رمز مستقل آن‌ها باید جداگانه بررسی شود.
- رمز ورود پزشک در Supabase نگهداری می‌شود و در این ارتقا تغییر نکرده است.
- نوبت حضوری و مشاوره متنی بر اساس برنامه هفتگی تعریف‌شده در پنل پزشک ارائه می‌شوند. مشاوره متنی پس از تأیید پزشک، پیوند ایتا را در حساب بیمار نمایش می‌دهد.
- دو وب‌اپ در مسیرهای جداگانه میزبانی می‌شوند. تغییر فایل‌های GitHub به‌تنهایی محتوای دامنه‌های تولیدی را تغییر نمی‌دهد؛ محتویات پوشه‌های web/patient/ و web/doctor/ باید در Document Root مربوط به خود بارگذاری شوند، مگر اینکه مسیر استقرار خودکار دیگری برای هاست تنظیم شده باشد.

## محدودیت امنیتی مهم
پیش از ورود اطلاعات پزشکی واقعی، بازبینی امنیتی، آزمایش حساب‌های قدیمی، بازیابی امن حساب، پشتیبان‌گیری مستقل و اعتبارسنجی بالینی باید تکمیل شوند. با این حال، قبل از ورود هرگونه داده پزشکی واقعی لازم است احراز هویت و بازیابی امن حساب، بازبینی امنیتی، پشتیبان‌گیری مستقل و اعتبارسنجی بالینی تکمیل شوند. نسخه فعلی فاقد پنل منشی است.
